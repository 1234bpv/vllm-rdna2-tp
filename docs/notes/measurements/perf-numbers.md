## Чому int4, а не int8 (21.08 → 31.08)

**Вузьке місце агентної роботи — префіл, а не декод.** Промпт Claude Code у
розробленій сесії доростає до 60 тис. токенів.

21.08 саме через це обрали int8: int4 був тоді вдвічі повільніший на такій
довжині (~110 проти 221 ток/с). **31.08 ця підстава зникла.** Після
переходу обох добутків уваги на цілі числа (Q·K через W4A8, P·V через
квантизацію P по рядку) шляхи зійшлися: на 74 тис. токенів int4 дає
273,4 ток/с, int8 — 270,5.

Швидкість однакова, тож обрано int4: він дає майже вдвічі більший кеш
(379 562 токени проти 203 337) і робить можливим вікно 262144.

⚠️ Ціна — якість: на стенді 9B перплексія int4 5,965 проти 5,940 у int8,
близько 0,4%. На 27B не міряно. Якщо якість важливіша —
`KV=int8_per_token_head` у `run-int4-mtp.sh`, швидкість буде практично та
сама.
